# Obsidian 同期プラグイン

[English](README.md) | **日本語**

Obsidian（ローカルの Markdown ノートアプリ）の保管庫（vault、Obsidian が開くローカルのフォルダ）と、[serverless-wiki-on-aws](../../README.ja.md) の読めるスペースを双方向に同期します。

## 機能

- Cognito（AWS の認証サービス）に OAuth 2.1 の認可コードフロー（PKCE つき）でサインインします
- 選んだスペースが保管庫の直下のフォルダになります。Wiki のフォルダーはフォルダのまま、ページは `タイトル.md` になります
- 1 サイクルで、プラグインが手元の変更（ノートとフォルダの作成、本文の編集、改名、移動）を Wiki へ送ってから、Wiki の変更を保管庫へ取り込みます
- サイクルは起動時、一定の周期（既定 5 分）、コマンドパレットの「いま同期する」で回ります
- 画像も両方向に運びます。Wiki の添付は `_attachments/<ページ ID>/` に落ち、保管庫で貼り付けた画像は Wiki へ上がります

## 前提

- Obsidian 1.5.0 以上
- デプロイ済みの Wiki と、そのアドレス、スタック出力 `McpClientId` の値
- プラグインをビルドする Node.js 24 と pnpm 11

## 導入

このプラグインはまだコミュニティのカタログに無いので、開発者がビルドして保管庫へリンクを張ります。

```bash
pnpm install                                    # リポジトリのルートで
pnpm run build                                  # このディレクトリで
node scripts/link-vault.mjs "/path/to/vault"
```

そのうえで、利用者が Obsidian の「コミュニティプラグイン」の制限モードを解除し、**sl-wiki Sync** を有効にします（プラグインの ID にはプロジェクトの短い名前が残っています）。

`link-vault.mjs` は `<保管庫>/.obsidian/plugins/slwiki-sync` からこのディレクトリへシンボリックリンクを張ります。
ビルドし直したあとは「アプリを再読み込み」で反映されます。
実体のディレクトリがある場合は、上書きせずに止まります。そこに利用者の設定とトークンがあるためです。

## 設定する値

| 設定 | 値 |
|---|---|
| Wiki の URL | Wiki を開くときのアドレスです。CloudFront 経由なら配信オリジン、`pnpm run sandbox` なら API Gateway の URL（末尾のステージ名 `/prod` まで含めます） |
| クライアント ID | スタック出力 `McpClientId` の値です |
| 同期するスペース | 「一覧を取得」を押し、保管庫に写したいものを有効にします |
| 手元で消したノートを Wiki からも消す | スペースごとに選びます。既定は無効で、手元で消したノートは次のサイクルで Wiki から戻ります。有効にすると Wiki のページを削除し、本文は取り消せません |
| 自動同期の間隔（分） | `0` にすると「いま同期する」だけになります |

サインイン画面のアドレスは入れません。
プラグインが Wiki の `/.well-known/oauth-authorization-server` を読むためです。
クライアント ID だけは引けません。この Wiki は動的クライアント登録（クライアントがその場で自分を登録する仕組み）を持たず、値はデプロイごとに変わるためです。

「同期の記録を消す」は、ページ ID とファイルの対応表を捨てて、次のサイクルで全ページを取得し直させます。
保管庫のファイルは消えません。本文が Wiki と同じファイルは、黙って対応表に戻ります。

## 食い違ったとき

**Wiki を正とします。この向きは設定で反転できません。**

- **両側で本文が変わったページ**：プラグインが手元の版を `タイトル (conflict 日付 時刻).md` として同じフォルダに残し、Wiki の本文で上書きします。置き場所が食い違ったときも Wiki 側を採ります。
- **片側にしか無いノートとフォルダ**：プラグインが反対側に作ります。
- **ノートを既に持つ保管庫**：最初のサイクルから上の規則が効きます。同じ場所の同じ名前のノートを、新しいページとしては送りません。

## 同期しないもの

- 退避したノート（`(conflict ...)` の付いたファイルを、新しいページとして送りません）
- `read` だけのスペース（取得専用になります）
- 兄弟の並び順（ファイルシステムに任意の並びを置く場所が無いためです。手元で作ったページは Wiki 側で末尾に付きます）
- 本文が指していない添付ファイルと、本文が画像として示していないもの（`image/svg+xml` は Wiki 側が受け付けません）

Wiki で消えたページは、プラグインが対応するノートを保管庫の `.trash` へ移します。

## トークンの置き場所

アクセストークンとリフレッシュトークンは、`<保管庫>/.obsidian/plugins/slwiki-sync/data.json` に平文で保存されます。
Obsidian がプラグインに与える保存先がここしかないためです。
保管庫を iCloud などの同期サービスに載せている場合、トークンもそこへ複製されます。
設定画面からサインアウトすると、Cognito 側でもリフレッシュトークンが無効になります。

## 開発

```bash
pnpm run build   # 型検査と main.js の生成
pnpm run dev     # 変更を監視してビルドし直す
pnpm run test    # 保管庫と Wiki を模した環境で 1 サイクルを回す
```

`pnpm run test` が動かすのは本物の同期エンジンで、通信は `test/wiki.ts`、ディスクは `test/vault.ts` が受け持ちます。
並べてあるのは、間違えたときの代償が大きい経路（両側からのフォルダの改名、中身ごとの削除、移行の直後）です。
サイクルは消す操作を持つ以上、「利用者が消した」の読み違いが、そのまま Wiki 側の削除になるためです。
